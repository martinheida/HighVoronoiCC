# HighVoronoiCC examples

The examples in this directory use the current public construction path:

1. create the generator nodes;
2. define a bounded domain;
3. construct a `VoronoiMesh` and its vertex database;
4. create a KD-tree nearest-neighbour backend;
5. create the appropriate `RayCaster`;
6. run `ComputeVoronoi` in serial mode;
7. validate the stored vertices with `verify_mesh`.

Both examples are deterministic and are derived from regression configurations
used by the test suite.

## General position

`general_position.cpp` constructs a bounded four-dimensional Voronoi diagram
for a reproducible pseudo-random generator set. It uses `ClassicRaycast`, which
is the appropriate path for vertices generated by exactly `dimension + 1`
generators.

The example demonstrates the basic construction API and then calls
`verify_mesh`. The verification checks geometric consistency of all stored
vertices, but does not by itself prove completeness.

Build and run only this example with:

```bash
cmake --build build/release --target highvoronoi_example_general_position
./build/release/highvoronoi_example_general_position
```

## Degenerate Cartesian grid

`cubic_grid.cpp` constructs the four-dimensional Cartesian generator grid

```text
{-3, -1, 1, 3}^4
```

inside the box `[-4,4]^4`. There are four generator positions per coordinate,
so the generator grid contains `4^4 = 256` nodes and represents three cubic
cell intervals per coordinate direction.

This configuration is strongly non-general: many generators belong to the same
Voronoi vertices. The example therefore uses `InRangeRaycast` and exercises the
degenerate edge iterator.

The exact bounded Voronoi vertices lie on

```text
{-4, -2, 0, 2, 4}^4,
```

so the expected number of primary vertices is `5^4 = 625`. The example checks
this count in addition to running `verify_mesh`.

Build and run only this example with:

```bash
cmake --build build/release --target highvoronoi_example_cubic_grid
./build/release/highvoronoi_example_cubic_grid
```

## Building all examples

Configure the project with examples enabled and build normally:

```bash
cmake -S . -B build/release \
    -DCMAKE_BUILD_TYPE=Release \
    -DHIGHVORONOI_BUILD_EXAMPLES=ON

cmake --build build/release
```

The examples currently use the serial construction path. Parallel construction
is part of the development roadmap and is intentionally not demonstrated here.
